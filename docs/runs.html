Suite: local-coding-v1, ten short Python tasks with hidden tests and partial credit (easy weight 1, medium 2, hard 3). Score is the weighted share of hidden tests passed, 0 to 100. Tokens/sec is the average generation speed across the run's tasks. Limits per task: 4,000 output tokens and 5 minutes with thinking off; 12,000 tokens (thinking included) and 15 minutes with thinking on. An answer cut off at a limit scores 0, so a low thinking-on score can mean the model spent its budget on thinking, not that its answer was wrong. Results are read from data/local-runtime-results.csv (one row per task) and the model list from data/local-test-models.csv; a row marked planned, not installed or cannot run has no numbers; the reason a model cannot run is in the model list.

Tiers with estimates

Every run model in its tier. A name or badge with * has no tier of its own: its tier is an estimated equivalent.

TierModels run locally

*estimated equivalent tier. Some local models are not in the long-coding data, so they have no official tier. Each is placed by its best local suite score against the models that do have a tier: the tiered models' scores form a line (suite score to % of Sonnet 5.5), the untiered model is put on that line by straight-line interpolation between the two nearest tiered models (clamped to the nearest one outside their range), and the usual tier bands apply (Tier 4 from 75%, Tier 3 from 55%, Tier 2 from 40%, Tier 1 from 20%). It is a rough guide, not a measurement: few models have both a tier and a run so far, and the estimate improves as more are run. Models not run yet stay at No tier. Estimated badges have a dashed outline.

Result per task

One column per run, best first. Each cell is the share of the hidden tests gained over the starter files, with the tests passed under it. An answer cut off at the token limit ("truncated") or the time limit ("timeout") scores 0.
